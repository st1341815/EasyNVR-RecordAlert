## 两件事：日报统计区间能跨夜了，告警推送能挑时段了；外加一个折行 bug 的修复

> 安装包：**EasyNVR-RecordAlert-1.0.17.fpk**（67455 字节，sha256 `013911d134d213ae515dd528848c7f143f251030eb2e9bc9c815d60569f46020`）
> 升级前请先读文末「升级注意」——**卸载会清空授权目录**，必须补一步。

### 一、日报统计区间可自定义

- 默认 `00:00 — 23:59`，等价于以前的「昨天整天」，升级后日报内容不变。
- `HH:MM` **含端点**，所以默认区间内部是 `[昨天 00:00, 今天 00:00)`，23:59 那一分钟不会丢。
- 起 > 止 = 跨天：`08:00 — 08:00` 是 24 小时，`18:00 — 06:00` 是 12 小时。
- 统计取「最近一个已结束的完整区间」：日报 09:00 发、区间 `08:00—08:00` 时，统计昨天 08:00 到今天 08:00。
- 正文改成 `统计区间：2026-11-03 08:00 — 2026-11-04 08:00`，跨天不再含糊写成「昨天」。
- 「补发昨日日报」改名「补发最近一期日报」（区间不再固定是昨天）。

### 二、推送计划：按星期 + 时段静默

- 新增「告警推送计划」：勾星期（一~日）+ 起止时段，默认「每天 00:00–23:59」= 全天。
  快捷按钮：每天 / 工作日 / 周末。
- **时段外（夜里、周末）只检测不推送**：扫描照常跑、状态页照常显示异常、日志照常记，只是不发告警。
- **而且不推进告警状态** —— 夜里断流不会被静默规则吃掉，进入时段后的第一轮扫描立刻补发一条。
- 跨夜时段（`22:00 — 07:00`）与「起止相同 = 全天」都支持；18:00 这种端点算在时段内。
- 页面「立即检测」= 人就在旁边看着，**默认绕过推送计划强制发一次**。
- 状态页新增「告警推送计划 工作日 08:00–18:00」，不在时段内时显示「（当前静默）」。
- **日报有自己独立的推送日**，不受告警时段影响 —— 关掉夜间告警不会顺手关掉日报。

### 三、界面：推送日不再折行（1.0.17）

- 推送时间的输入框收窄到 `9em`（约 126px，原满格约 289px）。
- 两组「推送日」改为独占整行、勾选项不折行。
- 375 / 560 / 700 / 768 / 900 / 1100 / 1440 px 七档宽度实测：单行、无横向溢出。

### 四、其他调整

- 日报的所有设置（开关 / 时间 / 统计区间 / 推送日）挪进「推送渠道」卡片，和渠道一次保存；
  「配置」卡片只管录像目录 / 布局 / 阈值 / 时区 / 别名。
- 容错：推送日空选或全是非法值 → **回落「每天」**，绝不让一次漏勾变成永久静默。
- 支持 `周一,周三` / `1 3 5` / `[1,3]` 三种写法；`8：00` 全角冒号照常归一。
- 旧配置没有这些键 → 全部取默认（每天 + 全天 + 00:00–23:59），行为与 1.0.15 一致。

### 升级注意（踩过，写下来）

`trim-cli app uninstall` 会**连「授权目录」一起清掉**：`/vol1/@appdata/erm` 里的
config.json / state.json / logs 都保留，但 `app config auth-paths erm` 变成空列表。
升级后不补这一步，应用一个录像文件都读不到：

```bash
trim-cli app config set-authorization-path erm /vol3/1000/NVR --perm 6 --yes
trim-cli app config auth-paths erm        # 必须能看到那条路径
trim-cli app restart erm --yes
```
