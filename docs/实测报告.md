| 版本 | 内容 |
| --- | --- |
| 1.0.0 | 首个可运行版本：manifest/wizard/privilege/路径/status 返回码/持久目录全部按飞牛规范重写；去掉 requests 依赖（纯 urllib）；判定基准改 `now - latest`；空目录/不可读也告警；日报改「到点即发 + 落盘去重」；推送校验 HTTP+业务码并支持钉钉加签。 |
| 1.0.1 | **修**：页面「立即检测」与后台线程各持一份 state → 同一条恢复通知发两遍。改为共享单一 `STATE` + 扫描互斥。 |
| 1.0.2 | 安装向导加 `rules` 校验（录像目录必填/必须是绝对路径、数字项、HH:MM）。 |
| 1.0.3 | **修**：pid 文件失效时 `stop` 杀不掉残留进程 → 两个实例同时扫描、重复发通知。加 `flock` 单实例锁；`cmd/main stop` 按脚本路径兜底清理。 |
| 1.0.4 | **修**：「停不下来」。HTTP/1.1 keep-alive 的 handler 线程让 `server_close()` 永久 join，收到 SIGTERM 只写日志不退出，应用中心卡在「停止中」。关闭 close 时的线程 join + 3 秒强退兜底。 |

> 1.0.3 的第一版还把单实例锁常量写在 `import config` 之前 → 启动即 `NameError`。
> 因此 `build.sh` 现在做 **真导入** 自检（`py_compile` 只查语法，查不出这类问题）。

### 4.6 推送正确性（这是原文档最容易"假成功"的地方）

```console
# 平台返回 200 但业务码失败
$ echo dingtalk_err > /tmp/erm-mock/mode; POST /api {"action":"test_push"}
ok: False   detail: "平台返回 errcode=310000 keywords not in content"    ← 原实现会记「已推送」

# HTTP 500
ok: False   detail: "请求失败：HTTP Error 500: Internal Server Error"

# 正确响应
ok: True    detail: "ok"    (0ms)
```

钉钉加签（`timestamp` + HMAC-SHA256 → base64 → urlencode）在 `selftest.py` 里与官方算法逐位比对通过。

### 4.7 日报（原文档这里永远不会触发）

原实现 `cur.hour == rh and cur.minute == rm` + `sleep(300)`：自检里用 05:18:42 起、288 个 5 分钟点跑一天，命中 08:00 的次数 = **0**。

现实现「到点即发 + 日期落 state」：

```console
# 把日报时间设成 05:36，等到点自动发
$ 重置后 last_report_day=（空）推送条数=14  05:33:41
$ 日报已于 05:36:22 自动触发 last_report_day=2026-10-29 推送条数=16

{"content": "【EasyNVR 录像日报 2026-10-28】\n统计区间：2026-10-28 00:00 — 24:00\n\n  stream_1：2 个文件\n  stream_2：0 个文件\n  stream_3：0 个文件\n\n合计：2 个录像文件（3 个通道）\n异常通道：stream_3（无录像文件）"}

# 重启后不再重复发
$ cmd/main restart; 重启前推送 16 → 一轮扫描后仍是 16
```

统计口径已按「昨天 00:00–24:00 的 mtime」验证：今天新录的 3 个文件不计入（只数到昨天放的 2 个）。

## 6. 未验证 / 已知限制

1. **应用中心 UI 的升级按钮**：命令行 `appcenter-cli install-fpk` 对已安装应用只回「已安装」，
   所以本次全部是 `uninstall` + `install`。UI 升级路径未验证；`upgrade_init/callback` 已按规范实现（停→起）。
2. **桌面图标**：本机 `autoCreateDesktopIcon` 未开，第三方应用只在「应用中心」出现（与 file.dedupe 一致）。
3. **重装后 `state.json` 会消失**（config.json 保留）→ 首轮按"首次发现"，不会补发历史告警。
4. **飞书/企业微信**：只做了响应码校验与自检 mock 验证，没有真实机器人可发（钉钉同样只有 mock）。
5. **HLS 录制模式**：`.ts` 分片会让"最新文件"永远很新，阈值需调小；日报的"文件数"不等于"录像条数"。
6. **外接存储**：`/vol00` 需「文件管理 → 设置 → 外接存储权限 → 所有账户可见」，授权目录对它无效（FAT 打不上 ACL）。

## 8. 追加（v1.0.5）：按 EasyNVR 真实目录结构重做通道识别

用户反馈实际录像目录是三层：

```text
/vol3/1000/NVR/easynvr_rec/O27fqV6dYvs3T/profile_1/20261029/20261029000315-62000.mp4
                 ↑录像根目录      ↑摄像头随机ID   ↑通道号   ↑日期     ↑录像文件
```

原实现只认 `<root>/stream_*` 一层，于是一个通道都识别不出来。v1.0.5 的改动：

| 项 | 改动 |
| --- | --- |
| 通道发现 | `<ID>/profile_N/<YYYYMMDD>/*` 三层；新增 `channel_layout`：`camera`（一个摄像头=一个通道，默认）/ `profile`（主/子码流各算一个）/ `flat`（老式一层） |
| 防误报 | 只把「含 `profile_N` 子目录」的目录当摄像头；缩略图/快照这类按日期分层的目录不再被当成通道 |
| 显示名 | 新增 `channel_aliases`（`O27fqV6dYvs3T=大门`），告警与日报显示「大门（O27fqV6dYvs3T）」（EasyNVR 的通道名存在它自己库里，目录里只有随机 ID） |
| 扫描性能 | 改为按 `<YYYYMMDD>` 目录逐天 `scandir`，不再递归整棵树；回溯上限 120 天。实测 **60 天 × 300 文件 = 18000 个 mp4，一次扫描 0.058 s** |
| 默认渠道 | `enabled_push_channels` 默认改为空（没配 webhook 时不再每轮记一条失败） |

验证方式：**不安装应用**，把 fpk 解开后以「已装好」的目录形态直接拉起 `server.py`（`TRIM_APPDEST` / `TRIM_PKGVAR` 指向临时目录），造一棵与现场一致的三层目录跑通：

## 9. 追加（v1.0.7）：手机端通道表溢出屏幕

**现象**：手机飞牛客户端打开应用，通道状态里的文本顶出屏幕。

**定位方法**：本地起 UI（`run_local_ui.py`，假 EasyNVR 三摄像头树），在页面里插一个
**390×844 的 iframe** 加载同一个页面 —— iframe 内的 media query 按自身宽度生效，等于真机视口，
可以直接用 `documentElement.scrollWidth` 量溢出，比改断点或猜快得多。

```console
# 修复前（390px iframe → 实际视口 375px）
vw=375  scrollW=555  overflow=180
溢出元素：TABLE w=520   TH「最新录像」w=136   TD「2026-10-29 12:27:00」w=136 ...
```

**根因**：
1. 表格所有 `th/td` 都是 `white-space: nowrap`（当初为了避免日期串和中文在窄列折行），
   6 列的 min-content 宽度被顶到 **520px**；
2. `.card` 没有 `overflow-x` 兜底 → 表格直接顶出卡片和屏幕（文档 `scrollWidth` 555px）。

**修复**（`app/www/index.html`，纯 CSS + `data-label`）：
- `≤640px`：通道表改为**逐通道卡片**（`thead` 隐藏，`tr` 变块，`td` 变「标签左 / 值右」两栏，
  长摄像头 ID `word-break: break-word` 可换行）；
- `.card { overflow-x: auto }` 作为任何宽内容的兜底；
- 表单控件 `font-size:16px`（防 iOS 聚焦自动缩放）；
- 无别名时「目录」列与通道名重复，手机上 `display:none`；
- 桌面端（>640px）布局不变。

**验证**（同一 iframe 探针，修复后）：

| 场景 | 视口 | scrollWidth | 溢出 | 被裁文字 |
| --- | --- | --- | --- | --- |
| 通道表 | 375px | 375 | **0** | 无 |
| + 一键自检表 | 375px | 375 | **0** | 无 |
| + 日志区 | 375px | 375 | **0** | 无（`pre` 在区块内横向滚动属设计） |
| 通道表 | 320px | 305 | **0** | 无 |

已部署到 `.6`（就地替换 `server.py` + `www/index.html`，属主 958，`app restart`，状态 running；
`state.json` 12:32 已刷新）。

## v1.0.8 配置瘦身（安装向导不再问目录/通道；删掉 stream_* 相关设置）

**背景**：实测现场反馈——安装向导要填「录像根目录」+「监控通道」、应用页面还有
「通道（逗号分隔，支持 `stream_*` 通配）」和「单层目录的自动发现规则」，
这四项和 EasyNVR 的真实目录结构
（`<录像根目录>/<摄像头ID>/profile_N/<YYYYMMDD>/<录像文件>`）**对不上**：
EasyNVR 不生成 `stream_*` 目录，通道清单手填只会填错。

**改动**：

| 位置 | 改动 |
| --- | --- |
| `wizard/install` | 第一步改为**纯说明**（`tips`，参照系统应用 `fn-ups-manager` 的用法），不再有 `wizard_record_root` / `wizard_monitor_channels` / `wizard_channel_include` 三个输入 |
| `wizard/config` | 删除「监控通道」输入，提示语改为「通道不用配，自动发现」 |
| `config.py` | 删 `monitor_channels` / `channel_include`；`channel_layout` 只接受 `camera`(默认) / `profile`，旧值 `auto`、`flat` 归一到 `camera`；两个废弃键在 `normalize()` 里被丢弃（下次保存 `config.json` 就干净） |
| `monitor.py` | 删 `detect_layout()`、显式通道清单分支、`flat` 分支；`resolve_channels()` 只按 `<ID>/profile_N` 发现；无通道时错误文案指出「录像目录要指向 easynvr_rec 这一层」 |
| `server.py` | doctor 的「通道布局」直接读配置（不再探测）；保存日志打印 `channel_layout` 代替 `monitor_channels` |
| `www/index.html` | 删两个输入框；布局下拉只剩两项；`LAY` 映射同步 |
| `apply_wizard.py` | 删两条废弃映射（`wizard_record_root` 保留：命令行 `-e install.env` 仍可预置） |

**兼容性**：

- 旧 `config.json`（含 `channel_layout: "auto"`、`monitor_channels: []`、`channel_include: "stream_*"`）
  直接可用，加载即归一；`save_config` 一次就把三个键从盘上清掉。
- 本机实测：升级后 `config.json` 键集合 =
  `alert_*/channel_aliases/channel_layout/daily_report_time/*_webhook/enabled_push_channels/notify_recovery/record_root/scan_interval/timezone/video_exts`，
  无 `monitor_channels` / `channel_include`。
